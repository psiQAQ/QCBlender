# QCBlender

English | [简体中文](README_zh.md)

QCBlender brings quantum chemistry data directly into Blender. It calculates orbital, density, and electrostatic potential grids from supported HF/DFT wavefunctions, and lets you inspect and adjust structures, isosurfaces, materials, and vibrations with native Geometry Nodes while retaining scientific units and provenance.

**QCBlender 0.1.0 Alpha Preview** targets Windows x64 and Blender 5.1.1. Release packages and status are listed on [GitHub Releases](https://github.com/psiQAQ/QCBlender/releases/tag/v0.1.0).

## Capabilities

| Task | Input | Output |
| --- | --- | --- |
| Molecular orbitals & electron densities | Gaussian `.fchk/.fch` or existing `.cube/.cub` files | Positive/negative orbital phases; total, alpha, beta, and spin density isosurfaces or volume displays |
| Electrostatic potential (ESP) | Supported FCHK or density/ESP Cube files | Density isosurfaces colored by ESP, fixed-range color bars, 2D slices, point probes, and line profiles |
| Properties & vibrations | Gaussian `.log/.out` or property-rich FCHK | Structures, method-specific energies, atomic charges, dipole moments, interactive normal mode playback, and IR frequency/intensity exports |
| Geometric trajectories | Gaussian optimization logs, IRC FCHK series, or multi-frame XYZ | Stepwise optimization/IRC geometries, convergence profiles, and discrete frame navigation |
| External analyses | Paired Cube files, point/path files, or tabular exports | IGMH/IRI, ESP extrema/area statistics, NBO/E(2), AIM critical points/paths, Mayer bond orders, and ETS-NOCV pairs (see [Import Guide](docs/EXTERNAL_ANALYSIS_IMPORT.md)) |

> [!NOTE]
> External analyses must be generated by their respective quantum chemistry software beforehand. QCBlender reads and visualizes the results; it does not perform SCF calculations.

## Compatibility & Installation

- **Tested Environment**: Windows x64, Blender 5.1.1 (manifest minimum: 5.1.1; upper version boundary: 5.2.0). Other versions and platforms are not covered by this validation.
- **Scope**: Non-periodic, real-valued, all-electron HF and DFT wavefunctions. Supported basis sets and methods are listed in [Validation Status](docs/VALIDATION.md).
- **Dependencies**: The extension bundles required scientific libraries. No external Python setup is needed.

### Method 1: Install from ZIP (Recommended)

1. Download `qcblender-0.1.0.zip` and verify its SHA-256 against `SHA256SUMS.txt` on [GitHub Releases](https://github.com/psiQAQ/QCBlender/releases/tag/v0.1.0). (Do not use GitHub's source code archive ZIP).
2. In Blender, go to **Edit → Preferences → Get Extensions**, click the top-right menu icon, choose **Install from Disk**, and select the ZIP file.
3. Switch to **Add-ons** in the Preferences sidebar, find **QCBlender**, enable it, expand its card, and click **Check Scientific Runtime**. Continue after the module status text reports that all checks passed.

### Method 2: Install from Remote Repository

1. In Blender, open **Edit → Preferences → System → Network** and enable **Allow Online Access**.
2. Go to **Get Extensions → Repositories → ＋ → Add Remote Repository**, enter `https://notes.psiqaq.cn/QCBlender/index.json`, and add it.
3. Refresh the repository, locate **QCBlender**, and click install. Check the runtime in **Add-ons** as described above.

The tutorial package (`qcblender-tutorial-0.1.0.zip`) contains the complete tutorial, screenshot assets, and sample files. Extract it while preserving the directory structure.

## Quickstart: Your First Molecular Orbital

Try the [P01 oxygen molecule example](validation/shared/data/public/gaussian-v2/P01/o2-uhf.fchk) in the tutorial package. Its FCHK contains the basis set and MOs needed for evaluation; follow the [full orbital walkthrough](validation/human/SOP.md#orbital) for a fixed Alpha MO9 example. Positive and negative surfaces represent orbital phase.

1. **Import Structure**: In the 3D Viewport, press `N` to open the sidebar. Go to **QCBlender → Import and Export → Import → Import Gaussian / Cube / XYZ**, then select the FCHK file.
2. **Open Object Settings**: Select the imported atom object. In the sidebar under **Current QC Object**, click **Open Object Properties**.
3. **Generate Field**: In **Create Views and Tools → Compute**, click **Generate Quantum Field**. Wait for the independent scientific preflight to pass, then use the parameter dialog:
   - Set **Quantity** to `Molecular orbital`, **Spin** to `Alpha`.
   - Select the target orbital by HOMO/LUMO or source number.
   - Adjust grid resolution (defaults to 0.2 Å spacing, 3 Å margin) and click **OK**.
4. **Tune Display**: Select the new field object and open its **Object Properties**. Under **Geometry Representation**, adjust the isovalue and toggles for positive/negative phases. Adjust surface colors under Blender's native **Material Properties**.
5. **Save Project**: In the N-panel under **Project and Maintenance → Save and Archive**, click **Save Self-Contained Project**. This creates a `.blend` file paired with a `.qcdata/` folder containing cached arrays.
6. **Render**: Position your camera, add scene lights, and press `F12` to render.

<details>
<summary>Default Grid Parameters and View Initial Values</summary>

- Initial grid: Spacing **0.2 Å**, margin **3 Å**, memory budget **512 MiB**.
- Atom view quality defaults to `Quality=3`; slice views sample **201** points per axis.
- Standard geometry node assets retain their bundled defaults.

</details>

<details>
<summary>Exporting Data & Parameter Summaries</summary>

Select the QC object containing the target records and navigate to **N sidebar → Import and Export → Export → Export Data and Parameter Summary**. The available data types depend on that object. Export original IR frequencies, optimization energy/convergence records, IRC records, Mayer bond orders, line-profile samples, paired-field voxels, or ESP area records as UTF-8 CSV files with `metadata.json`. **Current View Parameter Summary** instead exports `view-summary.md` and `metadata.json`. See the [shared export steps](validation/human/SOP.md#export).

Export files are saved to a dedicated subfolder within your project directory (or the system Documents folder if unsaved). You can set a global default path in add-on preferences.

</details>

## Project Saving & Scientific Constraints

- **Saving**: The `.blend` file holds nodes, materials, and scene layouts; the matching `.qcdata/` directory stores scientific arrays and provenance metadata. Always keep both together when moving or archiving projects.
- **Inputs**: Binary `.chk` files must be converted to text `.fchk` via Gaussian's `formchk` before import. For generic Cube files with unknown quantity or units, use **Identify Cube Quantity and Unit** after import, based on their generating calculation. Declaring a unit does not convert array values.
- **Current Limits**: Periodic boundary conditions (PBC), effective core potentials (ECP), complex wavefunctions, native ORCA formats, and Multiwfn `.mwfn` files are not supported.
- **Scientific Caveats**: Display bonds are inferred from atomic distances and do not represent calculated bond orders. Vibration playback is a visual representation and does not alter static wavefunction fields into time-dependent solutions.

Standard XYZ uses element symbols or atomic numbers and finite coordinates in Å. Multiple frames must retain atom count and element order; frame navigation is discrete, without interpolation or playback. Multi-frame XYZ cannot be associated as a static scientific reference. Single-frame association checks the actual geometry.

Save the latest project state before archiving; the archive uses the saved `.blend` and matching `.qcdata/`. Keep original calculation outputs separately. For research figures, retain method, basis, source identity, quantity/units, grid, isovalue and color range. The [current data notice](validation/shared/data/public/NOTICE.md) distinguishes owned public samples from historical restricted inputs; candidate checks and independent human/scientific acceptance are recorded separately in [Validation Status](docs/VALIDATION.md).

# Blender 交互与操作复用

本仓库维护者在开发和验收中按本页操作 Blender。跨历史操作记录统一保存在 [操作登记表](../acceptance/blender-operations.json)，产物保存位置仍由 [ARTIFACTS](../ARTIFACTS.md) 路由。

## 工具顺序

1. 操作前查询登记表，核对操作的已验证功能、参数范围、活动对象/选择顺序、Blender 版本、安装候选及相关实现摘要。
2. Computer Use 已实际成功执行且当前功能未变的操作，后续优先通过 Blender MCP 完成。每次仍检查当前工程的可观察结果；历史 GUI 通过不自动使本批数据或整个案例通过。
3. MCP 无法覆盖时使用已有命令行工具或 Blender 原生后台运行能力，记录命令、退出码及报告。后台进程也计入单 Blender 进程约束。
4. 首次操作、相关功能调整后的复验、需要确认界面/对话框/可见结果的变更、MCP 和命令行均不能完成时，使用 Computer Use。成功后更新登记表。
5. 用户明确要求本次重新点击某一步时按该要求执行。复用记录不免除权限、审批、用户工程保护和独立科研签署要求。

“功能未变”需要证据：优先比较对应操作实现、公共 helper、回调、接口与依赖的摘要；登记表的源码提交和完整产品树用于追踪。产品树不同但改动与该操作无关时，审阅具体差异并记录依据后可复用；无法确认影响范围时回到 Computer Use。只有文档、截图或证据索引变化不使已确认操作失效。依赖、Blender 版本或接口变化需复核适用性，不能仅比较 Operator 名称。

## 单进程与工程切换

- 同时只操作一个 Blender 窗口进程。主 Agent 串行持有 GUI 和 MCP；子 Agent 不同时连接或启动 Blender。
- 启动或重连前盘点全部 Blender PID、可执行文件和命令行。记录本批拥有的 PID、启动时间、配置目录及工程路径；MCP 首次调用只读返回 PID、版本、工程路径和未保存状态，与目标核对。
- 当前目标身份无法确认、多进程或 MCP 指向错误进程时，停止依赖该连接的写操作。先保全并正常关闭本批拥有的其他进程；用户已有进程不擅自关闭、保存、终止或覆盖。
- Blender 自己的渲染/文件选择子窗口属于同一 PID；交互时绑定实际返回的目标窗口，不能仅按窗口标题猜测归属。
- 一个工程完成后，及时执行“保存自包含工程”，核对 `.blend + .qcdata`、Dataset、数组及必要体积文件；保存日志和截图后正常关闭该进程并核对该 PID 退出，再开始下一工程。
- 冷重开按“保存 → 关闭 → 确认退出 → 新进程打开 → 核对 → 关闭”串行执行。移动或解包副本也如此，不同时打开多个 Blender 比较。
- 无输出或观察超时不证明退出。查询原 PID、同一任务/作业句柄与日志；不得因观测超时重复启动。必要停止只针对核对过的本批 PID，不按进程名批量终止。

## 记录与验收

每条操作记录包含稳定 ID、用途、GUI 验证状态、精确候选/源码、相关实现摘要、输入/对象/参数范围、实际入口、报告与截图摘要、MCP/命令行覆盖范围及限制。仅将真实执行且已确认结果的操作标记 `Passed`，未执行和失败分别记录 `Not Run / Failed`。

复用时在本批报告记录操作 ID、历史证据、相关实现未变依据、实际执行工具、PID、候选/输入摘要、参数、预期和实际结果。登记表的 GUI 历史证据保持原身份；新的 MCP 执行单独记录，不改写为本批 Computer Use 点击。

截图放在 SOP 对应步骤后，文件保存于 `docs/v1-acceptance/screenshot/`；保留用户复做占位。MCP/命令行执行后可用 Computer Use 仅观察并截图，截图说明应写实际操作工具，不冒称全部由点击产生。

本轮教程验收允许复用已有有效 GUI 操作，通过 MCP/命令行执行其余案例中的重复操作；每个案例要求的科学数组、错误输入、独立复制、渲染、工程保存/移动/解包冷重开结果仍须逐项验证。登记表未覆盖的操作首次通过 Computer Use 确认。用户操作、Agent 点击、MCP/命令行执行与独立科研签署分别维护，不替用户签名。

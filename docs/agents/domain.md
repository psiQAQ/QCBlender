# 领域文档规则

本仓库采用 single-context：根目录 CONTEXT.md 定义领域词汇，docs/adr/ 保存架构决策。

- 讨论或修改领域概念前读取 [CONTEXT.md](../../CONTEXT.md)；处理架构任务时读取 `docs/adr/` 中对应 ADR。理由：相同术语或接口建议必须遵守已有物理定义与架构决定。
- 新定义或决策明确后，通过可用的 `domain-modeling` 技能在上述位置维护。理由：已建立的领域文档是共同上下文，不需要重复初始化。
- `CONTEXT.md` 只记录领域定义，实施细节保存在设计与规格文档。理由：稳定的物理含义不应与易变化的模块和进度混写。
- 输出使用词汇表定义的术语；发现既有定义不符时先说明具体歧义。理由：例如轨道相位与电荷符号混用会改变读者对图像的科学解释。
- 建议与已接受 ADR 冲突时，引用该 ADR 并指出冲突，取得决策后更新。理由：单扩展交付等已确认边界不能被局部实现选择隐式替换。

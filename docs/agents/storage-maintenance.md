# 阶段产物与输入维护

阶段完成后，先保存用户仍需保留的工程，再集中必要输入、保存日志，最后清理已批准的生成物。2026-09-29 起，历史候选和全部渲染工程不再要求长期保留。本规则只覆盖用户批准的类别；新增类别、依赖环境变更、未知归属及用户工程另行确认。

## 执行顺序

1. 核对分支、工作区、Blender PID、可执行文件、当前工程及未保存状态。使用 **Save Portable QC Project** 另存到独立 `outputs/recovery/<会话>/`，保留 `.blend + .qcdata`，不覆盖已验收工程。
2. 在相同安装环境的新进程冷重开，核对 Dataset 身份、科学数组摘要和体积文件。保存/重开失败时保留原进程及相关数据；通过后正常关闭，仅核对该 PID 退出。
3. 保留受 Git 跟踪的 `tests/data/` 小样本。大型或受限许可输入复制到忽略的 `tests/data/local/`，核对原始字节 SHA-256；使用 `tests/data/local-inputs.json` 记录稳定 ID、路径、角色、用途和摘要，[SOURCES.md](../v1-acceptance/SOURCES.md) 是唯一人工阅读目录。CSV 优先使用相对路径；必须改写时另记清单新摘要，不修改其科学输入。
4. 更新测试读取入口；缺少必要输入直接失败，不新增跳过。依赖历史工程的检查应先从原始输入重建；显式工程参数仍可保留。运行相关科学回归和受影响 Blender 检查。
5. 生成逐文件清单，审查绝对路径、归属、用途、大小和保留/删除理由。确认无进程或保留工程仍依赖目标。跳过符号链接、junction、权限不明及未知归属项。
6. 按清单删除已批准文件，保留操作日志和未处理项。最后重新核对保全工程、软件环境非缓存文件、Git 标签和源码子模块；报告同一统计口径的实际空间变化。

## 分类边界

| 长期保留 | 完成验证后可清理 |
| --- | --- |
| 用户指定保留的工程及配套数据 | 其他历史生成 `.blend/.qcdata`、移动副本、截图和渲染 |
| 插件、配置、解释器、构建/测试工具环境和共享依赖 wheel | 重复候选 ZIP、确认可重建的构建结果、字节一致的重复 wheel |
| 必要波函数、Cube、分析表、CSV、原始计算日志、生成脚本及来源记录 | 已逐文件核对并更新入口的旧输入副本 |
| 参考原件、源码子模块、Git 历史/标签/归档清单 | 无引用的 worker 数据、场缓存、下载缓存、Python 字节码 |
| 验证报告、缺陷和操作日志 | 经核对属于已结束会话的临时文件和冗余恢复文件 |

`.log` 可能是科学输入，`.blend` 可能是安装包资产或用户配置；不得仅按扩展名删除。环境内部只能清理已确认的运行数据与缓存，不卸载插件或更改依赖。保留日志尽量留在原路径；输入迁移的映射说明其新路径。不得通过解除 ACL、取得所有权或全库 Git 回收扩大清理范围。

`tools/prune_outputs.py --plan` 只扫描仓库 `outputs/`，生成压缩 JSONL 逐文件清单和 `summary.json`；`--apply` 仅处理清单中的未变更文件，检查绝对路径和链接边界，核对受保护文件摘要。必须先完成上述前置验证并审查清单。再次清理应使用新的任务记录目录保存上一份清单，不能覆盖已有删除记录；脚本不替代用户对新增类别的授权。

## 历史结果与后续重建

历史 **Passed** 是当时执行结果，不因删除证据改写为新验证。相应技术记录须指向产物清理记录，并说明二进制是否仍可取得。后续需要安装包时从当前源码重建，记录源码提交和新 ZIP 摘要，重新执行安装资格检查；不能声称它逐字节复现已经删除的固定候选。

每阶段更新现有 [CHANGELOG.md](../CHANGELOG.md)：日期、用户可见变化、验证范围/状态、提交或标签、已知限制及产物保留状态。独立人工验收与外部视觉对照继续单独记录，Agent 不代签。

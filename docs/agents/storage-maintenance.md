# 阶段产物与输入维护

阶段完成后，先保存用户仍需保留的工程，再集中必要输入和有效结论，最后清理已批准的生成物。历史批次可按用户批准的摘要策略退役原始报告和二进制；当前候选及正在使用的证据保持可用。理由：生成物可能仍被打开的工程或下一次验证引用，必须先解除这些依赖。

历史候选和全部渲染工程不要求长期保留，但本规则只覆盖用户批准的类别；新增类别、依赖环境变更、未知归属及用户工程另行确认。理由：已批准的缓存清理不等于可删除任意同扩展名文件，授权范围须与逐文件用途一致。

## 执行顺序

1. 核对分支、工作区和 Blender 进程；存在需要保全的会话时，核对 PID、可执行文件、工程及未保存状态，使用 **保存自包含工程（Save Portable QC Project）** 另存到独立 `outputs/projects/<工程标识>/`，保留 `.blend + .qcdata`，不覆盖已验收工程。理由：`blender/project.py` 将科学数据与场景一起保存，单独复制 `.blend` 可能遗漏任务目录中的数组。
2. 保全后在相同安装环境的新进程冷重开，核对 Dataset 身份、科学数组摘要和体积文件；失败时保留原进程及数据，通过后正常关闭并只核对该 PID 退出。理由：保存返回成功不证明配套数据可以脱离原会话读取，按名称终止进程还可能伤及其他工程。
3. 必要输入集中在 `validation/shared/data/`：公开教程用 `public/`，本地限定及计算原件用 `local/`，自动测试小样本用 `regression/`。当前目录见[输入索引](../../validation/shared/data/README.md)，本地稳定 ID、路径、用途与摘要在 `local-inputs.json`。CSV 保持组内相对引用；Agent 在迁移前后核对原始字节，受限输入保持 Git 忽略。理由：人工和自动校验复用同一份当前输入，移动不能改变科学数据或丢失许可来源。
4. 更新测试读取入口；缺少必要输入直接失败，不新增跳过；依赖历史工程的检查先从原始输入重建，显式工程参数可保留。运行相关科学回归和受影响 Blender 检查。理由：删除 fixture 后跳过测试会隐藏能力损失，新工程才能证明重建路径仍然可用。
5. 生成逐文件清单，审查绝对路径、归属、用途、大小和保留/删除理由，确认无进程或保留工程依赖目标；跳过符号链接、junction、权限不明及未知归属项。理由：目录名和后缀不足以确定用途，链接还可能越过批准目录。
6. 按清单删除已批准文件，保留操作日志和未处理项；核对保全工程、软件环境非缓存文件、Git 标签与源码子模块，报告同口径的实际空间变化。理由：删除记录和保护对象摘要才能证明清理范围及空间收益。

## 分类边界

| 长期保留 | 完成验证后可清理 | 理由 |
| --- | --- | --- |
| 用户指定保留的工程及配套数据 | 其他历史生成 `.blend/.qcdata`、移动副本、截图和渲染 | 用户工程是交付资产；可重建展示结果的保留期限不同 |
| 最新待验收候选、一套共用构建/科学环境、锁定 wheels、必要许可证及活跃安装配置 | 已结束任务的独立 Blender 测试配置、旧候选、重复依赖和可重建构建结果 | 先核对共用环境、来源和活跃引用，再清理任务副本；不更新依赖版本 |
| 必要波函数、Cube、分析表、CSV、原始计算日志、生成脚本及来源记录 | 已逐文件核对并更新入口的旧输入副本 | 输入和计算条件决定科学结论，只有已核验迁移的副本可删 |
| 参考原件、源码子模块、Git 历史/标签/归档清单 | 无引用的 worker 数据、场缓存、下载缓存、Python 字节码 | 前者提供来源追溯；后者须先证明无引用且可重建 |
| 当前候选报告、历史 Markdown 结论、缺陷、原路径与摘要清单及删除收据 | 经摘要审查并获授权的历史日志、报告、截图、数组、工程和会话副本 | 摘要保留原日期、提交、候选、关键参数和 Passed / Failed / Not Run；用户工程及未知恢复对象独立保护 |

不得仅按扩展名删除。理由：`.log` 可能是科学输入，`.blend` 可能是安装包资产或用户配置。

共用及活跃环境只清理已确认的缓存；已保全且结束的任务独立环境可按明确策略移除。不得卸载用户现用插件、更新依赖或删除未知归属恢复文件。理由：共用能力和任务副本具有不同生命周期。

校验目录的新技术报告保存在 `validation/agent/reports/<日期>/<任务>/`；其他开发批次沿用 `outputs/evidence/<日期>/<任务>/`。历史摘要存入 `docs/archive/`，清单和收据使用压缩 JSONL；保留的原报告保持原始内容。摘要策略不得通过整批移动二进制到其他目录实现。必要输入集中到 `validation/shared/data/`，独有参考原件和完整许可保留一份并记录来源。理由：摘要降低历史存储量，原始科学输入和许可仍需逐字节追溯。

当前安装包在 `validation/shared/install/`，候选提交、原路径及验证收据由 `validation/agent/current-install.json` 定位。只选择最新完整且已有有效验证记录的包；科学数组和同版本 ZIP 不凭文件名判断相同。人工教程只使用安装文件，材料身份核对放在 Agent 流程。理由：人工作业可直接开始，技术来源仍可追查。

旧安装包及其匿名保全副本、重复数据、CI 外层容器和不完整下载分别列清单；已获用户批准的同目标、同范围类别按清单执行。迁移先复制核对，更新当前入口，再删除已批准的旧副本；精简映射与可用性记录随收据保留，不改写历史 Passed。匿名对象逐一核对所有旧路径及仍有效的引用；ZIP 包含唯一来源或保留对象时先证明成员覆盖。理由：同名和同大小不能证明副本身份，未知引用必须保留。

不得通过解除 ACL、取得所有权或全库 Git 回收扩大清理范围。理由：权限拒绝和历史可达性需要独立判断，不能用强制操作消除保护边界。

`tools/prune_outputs.py --plan` 只扫描仓库 `outputs/`，生成压缩 JSONL 清单和 `summary.json`；`--apply` 仅处理清单中的未变更文件并核对路径、链接和保护对象摘要。运行 apply 前必须完成上述前置验证并审查清单。理由：分类脚本无法自行证明某个工程已妥善保存或输入已迁移。

再次清理使用新的 `--report-dir <目录>`；可写入 outputs 或 `validation/agent/reports/` 的普通子目录，保留上一份清单和收据。新增类别仍须用户授权。理由：删除收据不可重建，也不能被后一次扫描覆盖或扩权。

## 任务策略与路由

`tools/prune_outputs.py --policy <JSON> --plan/--apply --report-dir <新目录>` 使用同一策略和清单，路径相对 outputs。`protected_paths` 保护文件或子树，`retained_references` 保护有有效引用的精确文件；`retired_task_roots`、`retired_profiles`、`migrated_files` 保留既有范围语义；`retired_files` 逐文件声明已审查退役项，可覆盖共用目录的默认保留。显式保护、Git 跟踪、当前报告与 recovery 始终优先；匿名对象只接受精确 `retired_files`。未分类文件、链接与未枚举目录原位保留。理由：目录默认策略只能作为起点，删除历史共享目录内容必须有逐文件依据。

先完成历史摘要、必要输入和来源审查、保留工程冷读及代表性重建，再生成删除清单。待删除文件必须有 SHA-256；apply 在任何删除前复核显式保护对象和集中输入，任一必需保护项失败则零删除。执行时再次核对内容、大小、修改时间、策略和路径，变化、权限拒绝、链接或缺摘要项原位保留。`removed.jsonl.gz` 记录成功删除的路径、大小与摘要；`applied.json` 保留失败阶段和原错误，报告独占创建。未知保留项扫描失败只限制其可验证范围，不自动扩大删除范围。

[ARTIFACTS](../ARTIFACTS.md) 是唯一产物路由入口，记录任务、日期、提交/归档标签、证据及工程位置、候选可用性、重建方法和阻塞。每次任务收尾同时更新路由、.scratch 状态、清理收据与 CHANGELOG；日志、策略及逐文件映射留在本批 evidence，临时工作放在 runs。不会根据清理结果自动改变独立科研签署。

权限失败交付准确绝对路径、原错误和逐文件 PowerShell 命令；重试脚本先复核清单摘要、文件内容、大小及修改时间。未知、受保护或无法建立身份的对象不进入命令。目录递归删除仅用于已完整枚举且全部可退役的目录；权限拒绝保持原位，不修改 ACL 或所有权。分别报告成功删除的逻辑字节、磁盘可用空间变化和未统计范围。

## 历史结果与后续重建

历史 **Passed** 只表示当时执行结果；技术记录须指向产物清理记录，并说明二进制可用性。理由：保留摘要和日志不等于旧 ZIP 或工程仍可取得。

需要安装包时从当前源码重建，记录源码提交和新 ZIP 摘要，重新执行安装资格检查，不宣称逐字节复现已删除候选。理由：源码或 ZIP 时间戳变化都会产生新的验证对象。

每阶段更新现有 [CHANGELOG.md](../CHANGELOG.md)，记录日期、用户可见变化、验证范围/状态、提交或标签、限制及产物保留状态。理由：演进记录让读者能定位当时的能力和证据，不需要第二份长期进度文档。

独立人工验收与外部视觉对照单独记录，Agent 不代签。理由：自动化数值与渲染检查不能代表使用者的独立判断。

## 保留产生实际价值的验证

标注 r1 的真实 GUI 连续创建暴露了小数精度历史继承：四类结果为 `[4,4,4,4]`，修复后同一入口复验为 `[4,4,2,2]`。Sidebar 的实际探针发现派生 `_atom_count` 与持久化元数据比较造成误报。圆弧批先在旧实现观察到半角回归失败，再核对安装后的原生几何、实际创建与渲染。这些检查对应具体行为，继续保留。

验证脚本也会失败：标注渲染夹具遗漏 XYZ 帧身份，Sidebar 脚本使用了不适用的动态 RNA/Event 属性；修正夹具后才得到有效结果。两个批次的 `Ctrl+Shift+Z` 注入观察到继续撤销，后续通过 Edit → Redo 菜单完成复验。产品失败、验证工具失败与输入注入失败分别记录，避免为错误前提扩大产品修改或测试范围。

最终整包验证同样必要。标注 r1/r2 的 96 个 Python 文件中 95 个哈希相同，但重建的三个节点 `.blend` 资产也改变了字节，因此 r2 独立执行最终安装、worker、资产渲染与中文冷读。实现未变的科学和交互证据可保留原身份复用，新 ZIP 仍需绑定自身的安装冒烟结果。

## 减少重复编排与重复执行

| 观察 | 调整 | 保留的边界 |
| --- | --- | --- |
| 多批重复维护会话、安装、快照、传输和归档脚本 | 统一调用 `python -m tools.dev_workflow`，复用已有底层工具 | 批次特有案例仍保留可审查输入和脚本 |
| 合入 main 后再次跑同一整套测试 | 核对源码、测试/输入、环境及候选身份后引用原报告 | 身份变化和受影响新改动重新验证 |
| 内部实现修改被扩大为全部 GUI 重验 | 首次入口及 UI 输入、弹窗、布局、交互变化才重验受影响入口 | 实际相关案例、必要渲染及用户指定点击继续执行 |
| 每批载入整个操作登记表和历史大报告 | 先关键词查询操作 ID 与摘要，再按需读取证据 | 查询结果来自原登记表，不建立第二份权威表 |
| 命令包装与完整输出占用主要阅读量 | 默认短输出、报告路径与失败原因，日志按需打开 | 真实错误、必要报告和候选身份仍保留 |
| 自动化保全未保存会话并辨认恢复草稿增加分支 | 用户先保存关闭，确认退出后开始；结束打开原保存工程 | 原文件、旧安装与偏好保护不减少 |

日常主线采用已有定向测试加一个实际相关案例，最终保留完整产品重建、隔离安装冒烟、已授权全局安装、必要冷读和原工程恢复。只有共享接口、依赖、科学定义或实际失败扩大影响范围时，才扩大测试集合。

本次精简不批量删除测试、历史脚本或验收资产；它改变后续任务入口和执行选择。发布 CI、精确候选 artifact、许可复核、独立试装与科研签署继续按既有门禁执行。后续以实际脚本复用量和执行记录观察收益；本复盘没有测得时间节省，也不把新入口的实现视为实际 Blender 验收通过。

当前执行规则见 [日常开发流程](development-workflow.md)，Blender 工具选择与操作记录见 [交互规则](blender-interaction.md)。
